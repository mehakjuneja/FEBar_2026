# Accord — Phase 2: ML Model (M1–M4) — Implementation Plan

> **How to use this plan:** task-by-task, **build → run → assert → commit**; `- [ ]` checkboxes.
> **Planning-only:** approach + the Databricks Assistant prompt to generate-then-own + verify. **You

> **⭐ HARD GATE:** this phase produces the **real ML model behind a serving endpoint** the FE Bar
> requires. A heuristic does not count.
>
> **Skills to load when building this phase:** `databricks-core` → `databricks-ml-training`,
> `databricks-model-serving`, `databricks-mlflow-evaluation`.

**Goal:** Train a model that recommends **Approve vs Hold** for each invoice line and expresses
**confidence**, register it in Unity Catalog, and put it behind a **live serving endpoint** the app
calls. Per decision **D-5**, the deterministic **exception code** comes from the rules in P3; the
**model** supplies the **hold-likelihood + confidence** and explainability — so the app can say
*"Hold — Price variance +6% vs PO, model confidence 0.94."*

**Architecture:** gold `invoice_match_result` + `line_truth` labels → a leakage-safe **feature/label
view** → MLflow-tracked training (gradient-boosted trees baseline) → **UC-registered model** →
**serving endpoint** → batch scores back to gold + a documented real-time contract for the app.

**Tech stack:** MLflow, Unity Catalog model registry, Databricks Model Serving, scikit-learn /
XGBoost (or LightGBM), SHAP for attributions, serverless.

## Global constraints

- **No leakage.** `line_truth.true_disposition`/`true_reason` are labels — never features. Features
  come only from what an analyst would know at invoice time (P3 discrepancy features).
- **Honest metrics.** Train/test split by time or vendor to avoid optimistic leakage; report against
  a **majority-class baseline** so "the model beats guessing" is provable.
- **Parameterized/portable:** widgets `catalog`/`schema_suffix`; no hardcoded literals or secrets.
- **Profile:** operator-chosen `--profile <name>`; never auto-select.
- **Naming** per spec §4: UC model `${catalog}.ml${suffix}.accord_holdrecommender`; endpoint
  `accord-holdrecommender`.

## Task M2: Train the Approve/Hold classifier (MLflow-tracked)

**Files:**
- Create: `ml/src/31_train.py` (notebook)

**Interfaces:**
- Consumes: `${catalog}.ml${suffix}.accord_features`.
- Produces: an MLflow run (params, metrics, model artifact, SHAP summary), and the best model
  staged for registration in M3.

**Approach:**
- [ ] Time-or-vendor-based train/test split.
- [ ] Baseline: majority-class (and a simple rules-only predictor) → the number to beat.
- [ ] Model: **gradient-boosted trees** (D-2); log AUC/PR-AUC, precision/recall **on the Hold class**
      (D-3: recall on Hold matters — a false approve pays bad money).
- [ ] **SHAP** feature attributions logged (D-5: this is the explainability the app surfaces).
- [ ] Pick the **decision threshold** by the cost asymmetry (favor Hold recall); record it as a
      model param so the app and batch scoring use the same threshold.
- [ ] Log everything with `mlflow.autolog()` + explicit metric logging; include an input example +
      signature (needed for clean serving).

**Databricks Assistant prompt (generate, then review & own):**
```

Log AUC, PR-AUC, and precision/recall/F1 for the HOLD class, comparing model vs baseline. Compute and
```

**Design checks / roleplay ammo:**
- **Why ML if rules already flag exceptions?** Rules give the *what* (exception code); the model
  ranks *hold-likelihood/confidence* to prioritize the queue and to learn vendor-level patterns
  rules miss. (D-5.)
- **Cost asymmetry** (D-3): a false approve pays bad money; a false hold costs analyst time and can
  miss early-pay discounts → threshold favors Hold recall. Be ready to defend the number.
- **Explainability**: SHAP top contributors are what the app's AI panel shows — the model isn't a
  black box to the analyst.
- **Leakage guard**: labels never enter features; as-of vendor stats; time-based split.

**Open items:** model family (D-2, GBT vs LR); whether to add a small **abstention** band (very
low-confidence → "needs review" instead of a firm rec) — nice AI-mindset touch for Exceeds.

**Exit criteria:** M1–M4 ✅; endpoint READY and scoring; `CONTRACT.md` written. Then Phase 3.
