# Accord — Phase 4: Invoice Reconciliation Workbench (A1–A6) — Implementation Plan

> The integrated, customer-facing surface. Work task-by-task; **build → run → assert → commit.**
> Planning-only: approach + wireframes + data contracts + verify — **you write and own the code.**
> Design: [`../specs/2026-09-24-accord-3way-match-design.md`](../specs/2026-09-24-accord-3way-match-design.md) §7.
>
> **Skills to load when building:** `databricks-core` → `fe-databricks-tools:databricks-apps`
> (scaffold/deploy) and/or `databricks-apps` / `databricks-apps-python` (if Streamlit),
> `databricks-model-serving` (serving client → `accord-holdrecommender`),
> `databricks-lakebase` (if chosen for decision/audit state, D-7),
> `fe-specialized-agents:web-devloop-tester` (local devloop/UI testing).

**Goal:** An **AP analyst workbench** that turns the gold match results into a workflow: see the
backlog, filter to what matters, understand *why* a line is held, and **bulk approve or reject** —
with an AI recommendation and an audit trail behind every decision.

**Architecture:** a Databricks App reading gold (`invoice_match_result`) + the audit/decision store,
calling the serving endpoint for per-line recommendations and AI Gateway (X1) for root-cause text,
and embedding the G1 Genie. Pages: **Summary → Reconciliation → Exceptions → Line detail →
Ask Accord.**

**Tech stack:** Databricks App (React+FastAPI *or* Streamlit — **D-4**), UC/SQL warehouse for
analytics reads, decision/audit store (Lakebase *or* Delta — **D-7**), Model Serving client, AI
Gateway.

## Global constraints

- **Human-in-the-loop:** AI recommends + explains; the **analyst decides**. Never auto-approve from
  the app.
- **Disposition state machine:** match sets `AUTO_APPROVED` | `HOLD`; analyst moves
  `HOLD → APPROVED` (incl. **bulk**) or `HOLD → REJECTED` (incl. **bulk**). Every transition writes
  an **audit** row (who / when / from→to / reason_code / note).
- **No secrets** in the app repo; auth via the app's managed identity + UC. Serving/AI Gateway
  endpoints resolved from config/env at runtime.
- Parameterized (catalog/endpoint names from config); profile operator-chosen.

> **Decide early (Phase-4 kickoff):** **D-4** framework — Streamlit = fastest "Meets," React+FastAPI
> = richer bulk-select grid + "Exceeds." **D-7** state store — **Lakebase** (Postgres) suits
> interactive row-level + bulk updates; Delta-via-SQL-warehouse is simplest and UC-governed.

## Task A3: Reconciliation review page (filters + bulk approve/reject) — core workflow

**Wireframe:**
```
Filters: [Supplier ▾][Year ▾][Month ▾][Week ▾][Reason ▾][$ min–max]     [Search]
☐ | Vendor        | Invoice#  | SKU     | $ at risk | Reason      | AI rec (conf) | Root cause
☑ | Atelier Nord  | INV-4821  | FR-119  | $2,140    | PRICE_VAR   | Hold (0.94)   | Unit price +6% vs PO
☑ | Rive Parfums  | INV-4830  | FR-052  | $980      | NO_RECEIPT  | Hold (0.88)   | No goods receipt found
[ Select all 640 ]        [ Bulk Approve ]  [ Bulk Reject ]   → writes audit rows
```

**Approach:**
- [ ] Query `HOLD` lines; join per-line serving score + X1 one-line root cause.
- [ ] **Filters:** Supplier, Year, Month, Week, reason_code, $ range — compose into the query.
- [ ] **Rank** by `amt_at_risk × hold_probability`.
- [ ] **Multi-select + Bulk Approve / Bulk Reject** → each writes an audit row and flips disposition;
      require a reason_code/note on bulk reject.

**Verify:** applying a filter narrows the row count to match the SQL; selecting N + Bulk Approve
writes N audit rows and moves them out of the `HOLD` queue.

## Task A5: Line detail (3-way side-by-side + AI panel)

**Wireframe:**
```
Invoice INV-4821 · line 3 · Atelier Nord
              PO-2207/1     GR-9910/1     INV-4821/3     match
 product_no   FR-119        FR-119        FR-119         ✓
 qty          40            40            40             ✓
 unit_price   34.00         —             36.10          ✗ (+6.2%)
 vendor       Atelier Nord  —             Atelier Nord   ✓
 uom          EA            EA            EA             ✓
┌ AI panel ───────────────────────────────────────────────┐
│ Recommendation: HOLD (confidence 0.94)                    │
│ Top factors: price_var_pct 0.062, vendor_hist 0.11 …(SHAP)│
│ Root cause: "Invoiced unit price $36.10 is 6.2% above the │
│  PO price $34.00 (tol 2%). Recommend hold for price var." │
│                        [ Approve ]  [ Reject ]  reason ▾  │
└───────────────────────────────────────────────────────────┘
```

**Approach:**
- [ ] Side-by-side PO/GR/Invoice with per-field match/mismatch chips (from `invoice_match_result`
      flags).
- [ ] AI panel: serving recommendation + confidence + SHAP top factors + **plain-language root
      cause** from X1 (AI Gateway); grounded in the actual field values.
- [ ] Single Approve/Reject with reason_code + note → audit.

**Verify:** panel renders a real serving response; approving writes one audit row; chips match the
gold flags.
